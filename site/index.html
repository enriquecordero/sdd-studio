Cómo funciona

Un spec, cuatro fases, cero sorpresas

Escribe tu idea en el chat, por ejemplo "quiero hacer el juego de Snake". El agente sdd-spec te pregunta con una tarjeta si es una funcionalidad, un bug o un Quick Spec, y delega cada fase en su subagente. Nada avanza hasta que tú lo apruebas, y las aprobaciones las aplica la extensión con código, no el modelo.

Requisitos

sdd-requirements

Historias de usuario y criterios de aceptación en formato EARS. Para bugs: comportamiento actual, esperado y lo que no debe cambiar.

✓ Aprobar requisitos → Diseño

Diseño

sdd-design

Arquitectura, interfaces, modelos de datos, errores y estrategia de tests, a partir del código real del repo.

✓ Aprobar diseño → Tareas

Tareas

sdd-tasks

Plan de implementación en tareas pequeñas, cada una trazada a los criterios que cubre.

✓ Aprobar tareas → Implementar

Implementación

sdd-implement

Una tarea por vez: test primero, código mínimo, verificación real. Tú confirmas cuándo está hecha.

Características

Lo de Kiro, en el editor que ya usas

Construido solo con funciones GA de VS Code y Copilot: custom agents, prompt files, instructions y herramientas de extensión.

🌲

Panel Specs

Cada spec con su fase y progreso. Aprueba documentos y ejecuta o marca tareas desde el propio árbol.

▶

Ejecutar tarea

Un clic sobre la tarea la marca en curso y abre Copilot con sdd-implement, la tarea y sus requisitos como contexto.

🔒

Aprobaciones deterministas

Las herramientas sdd_* cambian estados con código. Los agentes de requisitos, diseño y tareas no pueden tocar tu código.

🧭

Steering nativo

product, tech y structure como instrucciones de Copilot: guían también cualquier chat normal.

⚡

Quick Spec

Cuando tienes prisa: requisitos, diseño y tareas generados de una vez, listos para ejecutar. Desde la tarjeta o con /spec-quick.

💬

Empieza desde el chat

Sin formularios: "+ Nuevo spec" abre Copilot con sdd-spec. Te pregunta lo justo con tarjetas clicables y elige el nombre del spec por ti.

🐞

Specs de bugfix

Comportamiento actual, esperado y de regresión, causa raíz en el diseño y un test que reproduce el bug primero.

🩺

Diagnóstico

Comprueba Copilot, agent mode, herramientas de extensión y políticas de empresa, y te dice qué pedir a TI.

↩️

Seguro con tus archivos

Todos los cambios pasan por el editor: respetan Ctrl+Z y nunca pisan un documento con cambios sin guardar.

📁

Multi-root

Cada carpeta del workspace con su propio specs/, agrupadas en el panel.

🎨

SDD Studio Dark

Un tema morado inspirado en Kiro. Se ofrece una vez; nunca se activa sin preguntarte.

Formato

Markdown legible, versionado con tu código

Todo vive en specs/<feature>/. Sin bases de datos ni archivos de estado ocultos: el estado está en el front matter y en las casillas.

Instalar

Listo en dos minutos

Se distribuye como un archivo .vsix. Necesitas GitHub Copilot con agent mode habilitado.

  1. Consigue el .vsixDesde los Releases del repo, o genéralo tú con npm run package.
  2. InstálaloCon el comando de la derecha o arrastrando el archivo a la vista de Extensiones.
  3. Ejecuta "SDD Studio: Diagnóstico"Comprueba Copilot y las políticas de tu organización.
  4. Abre el panel ⚡ y crea tu primer spec"+ Nuevo spec" → escribe tu idea en el chat → elige el tipo en la tarjeta. Copilot hace el resto, y tú apruebas.
# instalar $ code --install-extension sdd-studio-0.3.4.vsix # o compilar desde el código $ git clone https://github.com/enriquecordero/sdd-studio $ cd sdd-studio && npm ci $ npm run package
  • VS Code 1.140 o superior
  • GitHub Copilot Chat con sesión iniciada y agent mode habilitado
  • Comandos de chat: /spec-new, /spec-bugfix, /spec-quick, /spec-run, /spec-steering
